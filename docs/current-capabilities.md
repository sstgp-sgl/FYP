# 当前项目能做什么

本项目把三件事连接起来：从照片得到主体三维资产、按空间要求摆放资产、把故事生成可检查的三幕画面。

## 可以实际操作的流程

1. 上传一张图片，在网页点击要重建的主体，查看 SAM2 前景掩码。多主体照片可以对不同主体分别选点、分别重建。
2. 选择 VGGT（配合 Zero123++）、TripoSR 或 Hunyuan3D-2mini。输出统一 PLY 点云和来源/参数记录；后两个适配器目前只输出灰色几何。
3. 选两到三个已登记、名称不同的资产，输入受支持的简单故事。系统调用 DeepSeek 生成结构化关系与事件，再用确定性程序布局、渲染并独立验证。
4. 查看三幕图片、旁白、逐幕验证，下载 ZIP。刷新网页后从历史继续查看；重复提交同一个请求不会重新执行。
5. 对已成功的故事修改指定幕的旁白、overview/focus 镜头、已有 near/far/左右关系或距离。可直接选择表单，也可输入一句局部修改要求。
6. 修改以版本保存。其他幕默认锁定，失败不会覆盖有效旧版；可以查看历史版本。新版本会重新检查全部跨幕事件，冲突会返回报告。

## 建议怎样看效果

先按 README 的 CPU 演示确认安装；它只展示合成方块，不需要 GPU 或密钥。

查看真实效果时，使用 HPC 已登记的“人物”和“熊”，生成简单的“相隔—靠近—保持”故事，查看三张图片是否与旁白一致。修改时先只改第二幕旁白，再只改第二幕镜头：第一、三幕应保持不变，镜头修改不应移动物体。最后尝试一个与锁定幕事件冲突的修改，检查系统是否拒绝并保留旧版本。

完整图片重建需要 GPU 作业；已有点云的故事渲染和 P7 编辑可以在 CPU 作业中完成。P7 验收服务会显示 CPU 运行范围，不执行新的分割/重建。资产库、权重、历史状态和密钥均不随 GitHub 源码上传。

## 现在还不能保证什么

- 单图重建不能恢复不可见表面的真实几何。熊的背面、四肢连接可能不准，人物仍有缺面；流程跑通不代表重建质量已解决。
- 真实资产的上方和前方仍可能是候选方向，需要人工确认。名称确认和朝向确认是两件事。
- 画面是静态点云刚体分镜，没有骨骼动作、连续动画、真实接触或物理仿真。距离是相对场景单位，不能当作照片中的真实米数。
- 几何验证检查程序保存的坐标、边界、可见性和定义的事件。它不等于人类理解完整故事，也不能证明自然语言旁白的所有句子属实；改关系后应特别检查旧旁白是否仍合适。
- 自然语言编辑可能理解错误。结构化修改的正确性和语言解释的成功率必须分别报告，不能以一项代替另一项。
- 当前为 SSH 隧道中的单用户研究原型，不提供公网多人协作、任意代码/矩阵编辑，也没有自动纹理生成或视频配音导出。

## 接下来需要做什么

优先人工检查并整理重建资产，确认名称、朝向和可接受的形状；质量较差的资产单独标记。这样可以避免把资产缺陷误判成故事规划错误。

计划中的 P8 是冻结测试集、比较基线/消融、记录失败、耗时和人工评价。测试集应与已调试示例区分，并分别评价几何资产、空间/事件执行、旁白语义和可读性。目前的少量成功演示不能充当正式论文效果结论。

纹理和更好几何可以单独继续改进；字幕视频和音频属于可选 P9。完成 P7 不会自动开始 P8 或 P9。
