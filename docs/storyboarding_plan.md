# 基于图片资产的语言驱动三维故事板：分阶段实施与验收计划

**English title:** Language-Guided 3D Storyboarding with Reconstructed Image Assets
**版本：** 1.0；2026-11-17
**对象：** 项目负责人（你）与负责实现的 Codex
**仓库：** https://github.com/sstgp-sgl/FYP
**文档性质：** 待执行计划，不代表所列功能、测试或质量指标已经完成。

## 1. 项目定义与最终交付

用户上传两至三张主体图片，经现有 SAM2 → Zero123++ → VGGT 流程获得可独立摆放的彩色点云资产；用户输入一个简短故事，系统将其转换为三幕场景、三张故事板画面及对应旁白，并允许修改某一幕。

第一版交付的是可解释、可修改的三维故事板。每一幕是一个静态三维场景状态，不要求人物骨骼动画、连续行走、布料、水面或真实物理模拟。以点云为主表示，不要求转换为 mesh。SHARP 不属于本计划主线。

### 1.1 最小验收示例

输入两个资产：`boat_01`（小船）、`lighthouse_01`（灯塔）。用户要求：

> 第一幕小船在灯塔左侧且较远；第二幕仍在左侧，但明显靠近；第三幕保持在灯塔附近。请写三段表达寻找方向的简短旁白。

输出：

| 产物 | 必须包含 |
|---|---|
| 资产登记 | 原始点云、来源图片、哈希、坐标变换、人工确认的名称 |
| StoryPlan | 三幕事件、对象引用、空间约束、旁白、关注对象 |
| SceneState × 3 | 每个实例的实际变换、约束与检查结果 |
| ShotPlan × 3 | 相机参数、画幅、目标、裁切检查 |
| 故事板 | 三张实际渲染 PNG 与独立文字旁白 |
| ValidationReport | 空间、跨幕状态、引用与镜头检查，保留失败原因 |
| 运行记录 | 代码版本、配置、输入、模型、耗时、输出路径和状态 |

“灯塔提供了方向”可以作为创作表达；“小船移动到了左侧”必须与场景一致。画面只表达静态状态和幕间变化，不声称生成了完整动作动画。

### 1.2 研究问题

主问题：**在用户提供的重建资产上，显式空间和事件约束能否提高语言故事到三维故事板的执行一致性？**

候选假设：

- H1：输出关系再计算位置，比让 LLM 直接输出位置更容易满足用户空间要求。
- H2：加入独立检查和有限修正，能降低非法引用、场景冲突和事件不一致。
- H3：保存结构化场景状态，可减少局部修改导致的无关变化。

这些是假设，不是已证明的创新或效果。最终论文以实验支持的结论为准，不以“用了多个模型”作为贡献。

### 1.3 范围控制

| 必须完成 | 通过核心验收后再做 | 本轮不做 |
|---|---|---|
| 2–3 个资产、3 幕、手动确认名称 | 多张候选故事板、自动命名 | 大型开放场景自动生成 |
| 点云资产导入、布局与渲染 | 网格或更漂亮的渲染 | 重训 SAM/VGGT/生成模型 |
| 地面摆放、左右、远近、状态保持 | 更多关系、更多幕 | 抓取、坐下、拿起等复杂动作 |
| LLM 结构化故事、有限修正 | 多 agent 作为额外消融 | 把多 agent/harness 作为独立开发主线 |
| 可复现实验和逐阶段产物 | 简单字幕视频、TTS | 完整动画短片或视频生成模型竞赛 |

### 3.1 每阶段工作节奏

1. Codex 读取当前阶段与上一阶段报告，列出本阶段具体改动。
2. 连续完成该阶段授权范围内的编码、测试和修复，不每条命令询问用户。
3. 自动测试通过后，提供实际产物、运行命令和人工验收项目。
4. 你完成需要视觉/叙事判断的检查；未通过则在本阶段修复。
5. 阶段报告记录为 `passed`、`failed` 或 `blocked`；通过后根据你的下一阶段指令推进。

首次给 Codex 时建议仅执行 **P0 和 P1**，到达第一个可检查的闭环后停止扩展。后续每次执行一个阶段。本计划本身不触发修改仓库、发布服务或大批 GPU 作业。

| 层 | 采用技术 | 初次引入阶段 | 约束 |

| 存储 | JSON、PLY、NPZ、PNG | P1 起 | 原子写入、哈希、运行隔离，首版无需 Redis/Celery |

| 导出 | FFmpeg | P9 | 首版不要求 TTS、连续运镜 |

环境分离：

- `recon`：使用实际已经验证的旧重建环境。
- `story`：轻量编排、几何、渲染、网页、测试；先核对现有环境能否直接承载。
- `vlm`：独立模型环境。Qwen3-VL 官方说明要求 Transformers >= 4.57.0，而此前查看的重建依赖为 4.44.2；不要直接升级旧环境。

具体版本在 P0/P5 中经实际测试后锁定，分别输出 requirements/环境快照；本计划不假造尚未测试的完整兼容版本组合。模型环境通过 JSON 文件或本机 HTTP 接口通信，禁止在主业务模块顶层导入所有大模型。

使用单张 GPU 时，先串行运行重建和 VLM，保存中间结果，避免同时常驻。HPC 上重型推理遵循实际调度器配置，在获分配的计算节点执行；不假设登录节点有 GPU。所有主机、项目路径、环境路径和端口配置化，不能写死旧 AutoDL 地址。

## 6. 数据接口、坐标与语义约定

### 6.1 对象契约

| 对象 | 关键字段 | 不变量 |
|---|---|---|
| 资产（复用 AssetRecord） | asset_id、representation、relative_path、sha256、source_kind、coordinate_frame、unit | 原文件不可变；point_cloud 与 gaussian_splat 不混淆 |
| 资产语义侧文件 | asset_id、display_name、aliases、source_image、confirmed_by_user、allowed_roles | 名称不等于几何 ID；自动标签未经确认不得当作真值 |
| StoryPlan v1 | story_id、schema_version、asset_ids、premise、scenes、provenance | 每幕都引用已登记资产，场景 ID 唯一 |
| SceneIntent | scene_id、base_scene_id、constraints、events、focus_instance_id、narration | 继承关系无环；事件必须可编译 |
| StoryConstraint | constraint_id、subject_instance_id、relation、object_instance_id、frame、parameters | 不改变旧 PlacementConstraint 只支持左右的含义 |
| CompiledScene | scene_document、resolved_constraints、event_checks | 实际坐标与计划分开保存；不能只保存自然语言 |
| ShotPlan | shot_id、scene_id、template、target_ids、projection、K、T_world_from_camera、width、height | 矩阵与约定明确，不能只给 position/look_at 而不记解释 |
| Narration | text、entity_refs、fact_claims、creative_text | 可检验事实与创作表达分开，事实引用稳定 ID |
| EditPatch | base_version、target_scene_id、operations、preserve_fields | 版本冲突时拒绝覆盖；更新是事务性的 |
| ValidationReport | checks、measured、expected、tolerance、status、evidence_paths | failed/unchecked 不得伪装成 passed |
| RunRecord 扩展侧文件 | code_commit、config_hash、input_hashes、provider、attempt、stages | 与已有 RunRecord 通过 run_id 关联，避免破坏旧读者 |

Pydantic schema 负责字段和范围；独立 validator 负责实际坐标、图像可见性、跨幕事件与用户要求。纯文学一致性仍需人工评价。

### 6.2 空间约定

- 沿用右手系、Y 轴向上、地面 y=0；列向量，`p_world = T_world_from_asset @ p_asset`。
- 内部四元数沿用现有 `xyzw`。Viser 若需要 `wxyz`，只在适配边界转换并测试。
- 场景正面观察方向固定，场景 +X 为正面参考视角的右侧。`left_of` 不随交互查看器旋转改变。
- 默认单位 arbitrary。资产高度归一化为配置值只是创作尺度，不表示真实米制。
- 原始 VGGT 输出不能默认 Y-up。通过已知上方向或人工旋转确认保存 `source_to_canonical`；无法确认则标记 `needs_orientation`。
- canonical 点集先完成朝向、底部中心与尺度变换；场景实例变换再应用一次。保存/加载不能二次应用 canonical 变换。
- 计算变换后的 AABB 时变换原始边界的八个角，不能只变换 min/max 两点。第一版自动布局固定 yaw，避免引入额外旋转搜索。

### 6.3 支持的空间关系

第一版保留关系集合小且可测试。默认参数以固定归一化场景单位 U 表示，P0/P3 冻结并写入配置。

| 关系 | 数值定义 | 默认示例 |
|---|---|---|
| left_of(A,B) | A 的 max_x + gap <= B 的 min_x + eps | gap=0.2U |
| right_of(A,B) | A 的 min_x >= B 的 max_x + gap - eps | gap=0.2U |
| near(A,B) | 地面投影 AABB 间最短距离 <= near_max；另验非重叠 | near_max=0.5U |
| far(A,B) | 同一距离 >= far_min | far_min=1.5U |
| on_ground(A) | abs(min_y(A)) <= eps | eps=1e-4U |
| keep_pose(A) | 相对基幕的平移/尺度/旋转差在容差内 | 平移/尺度 1e-6，角度 1e-5rad |
| non_overlap(A,B) | 地面 footprint 无超过容差的正面积相交 | 允许边界接触；不支持堆叠 |

AABB 非重叠是保守近似，不等于精确物理碰撞检测。near/far 的默认阈值是本系统操作定义，不能称作普遍语言真值。测试集期望在运行模型前独立标注。

### 6.4 跨幕事件

- `approach(A,B)`：两幕地面投影中心距离减少至少 `min_change=0.2U`。
- `retreat(A,B)`：该距离增加至少同样幅度。
- `hold(A)`：实例变换保持。
- `appear(A)` / `disappear(A)`：只切换可见性，不创造或删除资产文件。

事件可同时带终态约束，例如 approach + near。不能将“靠近了一点”自动解释为最终 near。不支持的动作返回 `unsupported_action`，允许用户修改故事；不能默默把“拿起”改成“靠近”然后宣称成功。

### 6.5 初始 API 与 CLI（均为待实现接口）

CLI 使用占位解释器 `$PY`，执行前由 P0 设置真实路径；以下新命令不代表当前仓库已有。

```bash
$PY scripts/storyboard.py demo --config configs/storyboard.yaml --out outputs/storyboard/p1-demo
$PY scripts/storyboard.py validate --run outputs/storyboard/p1-demo
$PY scripts/storyboard.py import-asset --ply INPUT.ply --metadata ASSET_METADATA.json
$PY scripts/storyboard.py compile --plan PLAN.json --config configs/storyboard.yaml --out RUN_DIR
$PY scripts/storyboard.py plan --request REQUEST.json --provider-config PROVIDER.yaml --out RUN_DIR
$PY scripts/storyboard.py edit --run RUN_DIR --request EDIT.json --out NEW_VERSION_DIR
```

API 草案：`GET /api/storyboard/assets`、`POST /api/storyboard/runs`、`GET /api/storyboard/runs/{id}`、`GET /api/storyboard/runs/{id}/artifacts/{artifact_id}`、`POST /api/storyboard/runs/{id}/edits`。创建任务返回 202 + run_id，网页轮询状态。API 不接收任意服务器绝对路径，按登记的资产和产物 ID 查找。

**Gate P1**：所有上述行为有证据；正例通过、负例失败；不需要真实 LLM/GPU；旧场景命令不被破坏。只实现数据类而没有实际图像，不算完成。

**Gate P2**：至少两个真实资产能在同一场景摆放并展示。只有合成资产通过时，明确 P2 未完成。不存在几何真值时不报告 Chamfer/F-score。

### P3：受控空间语言与确定性布局

**输入**：结构化约束 JSON，由人或 fixture 提供，暂不接 LLM。

**Codex 任务**

1. 实现第 6.3 节关系、单位和阈值；对未知关系明确拒绝。

4. 所有结果经独立 validator 验证才能接受；不能将优化器 success 当作约束成立。
5. 检测明显矛盾，例如同时要求同一对象对同一锚点 left_of 与 right_of 且 gap>0。

### P8：基线、消融、正式实验与论文材料

**数据层次**

- 几何单元测试：小型合成点云与手工数值答案，验证代码逻辑。
- 开发集：15 条故事用于 prompt/阈值/预算调试。
- 冻结测试集：建议 30 条故事任务，来自 10 组资产组合，每组 3 种故事；每种方法重复 3 次。
- 重建适用性：另准备至少 6 个真实资产（来自不少于 3 类主体），覆盖浅色、不规则和一个较差样本。记录筛选与淘汰原因。
- 拆分以资产组/来源图片为单位，测试组不参与调参；条件不足时披露共享资产导致的评估范围限制。

30 × 3 次 × 3 主方法 = 270 次规划运行是建议正式规模。先在 5 个任务上试运行，估算耗时/费用，再确定可承担的冻结规模。不要在 P0–P7 提前执行全量实验。

**主比较**

| 方法 | 输入与模型 | 输出与执行 | 检查/修正 |
|---|---|---|---|
| B0 Direct coordinates | 同一用户故事、资产表、模型 | LLM 直接输出每幕坐标和旁白 | 基础解析保护；无语义修正 |
| B1 Relations | 相同输入、模型 | LLM 输出关系；确定性布局 | 无 LLM 反馈修正，照常记录失败 |
| Ours | 相同输入、模型 | 关系与事件编译、状态保持 | 独立验证 + 最多两次修正 |

所有方法使用同一资产、渲染器、镜头模板、画幅、模型、旁白长度范围。B0 也能访问相同资产尺寸与单位信息，不能故意让其缺少信息。所有方法均接受统一最终评价；“不修正”不等于“不记录错误”。

额外预算控制：Ours 可能调用三次模型，另做 B0/B1 同调用上限重试的敏感性对照，报告质量—耗时—调用数；不能把更多调用带来的收益全归因于结构设计。

**主要指标定义**

| 指标 | 定义 | 方向 |
|---|---|---|
| 用户空间要求满足率 | 满足的人工标注要求数 / 所有要求数 | 高 |
| 事件满足率 | 实际场景中成立的预标注跨幕事件数 / 事件总数 | 高 |
| 故事完全成功率 | 所有必需关系/事件/产物满足的任务数 / 全部任务数 | 高 |
| 引用正确率 | 合法且与用户对象对应的引用数 / 全部引用数 | 高 |
| 目标可见率 | 预定关注对象达到可见标准的幕数 / 应展示幕数 | 高 |
| 旁白事实支持率 | 由画面/状态支持的可检验原子陈述数 / 全部可检验陈述数 | 高 |
| 未指定内容改变率 | 被改变的锁定语义字段数 / 锁定字段总数 | 低 |
| 运行代价 | 总时间、LLM 调用数、token/API 费用（可得时）、失败数 | 低 |

空间与事件指标以用户任务的独立人工标注为分母，不以模型自行输出的约束为分母，防止漏掉难要求而得高分。规划失败、解析失败、渲染失败计入端到端失败；同时报告各失败类别。纯创作句不进入事实支持率分母，单独评叙事连贯与表达。

旁白自然语言不能仅靠其 `fact_claims` 自报判断正确。标注员阅读完整旁白与图片，核对其遗漏和无依据内容。

**消融**：去除状态继承；去除约束反馈修正；固定镜头与自适应取景比较。一次只移除一个机制，其他条件固定。

**统计**：先在同一任务内汇总重复运行，再按资产组/任务做配对比较；报告均值/中位数、分布和置信区间，不将同一故事的三幕当作三个独立样本。小样本结果明确为探索性。

**人工评价**：条件允许邀请 8–12 位同学，每人查看平衡随机抽取的比较对，隐藏方法名；记录看图理解正确率、连贯性、修改任务完成时间。先写标注规则，对部分样本由两人独立评分并报告一致性。人数不足时如实报告，不声称广泛用户结论。

**Gate P8**：冻结配置与 commit；独立输入/答案；基线及失败记录完整；能通过一条评估命令重建结果表；论文区分重建质量、代码正确性与叙事质量。

### P9（可选）：字幕视频与音频

从已验收故事板导出图片停留与硬切视频；此时不引入新相机规划研究。先字幕后 TTS，若接 TTS 根据实际音频时长安排停留；文本长度估计不能代替测量。

测试分辨率、总帧数、每段时长、字幕字体、音画对应。FFmpeg 不存在时输出清楚依赖错误。视频导出失败不能破坏已完成的故事板结果。

## 8. 运行状态、缓存与失败恢复

阶段状态使用 pending/running/succeeded/failed/interrupted；缓存命中作为显式字段，缺失产物不得算命中。故事板只有全部必需幕成功才算 succeeded；部分幕失败为 partial_failed，仍允许查看已有内容。

缓存按以下依赖失效：

| 变化 | 必须重算 | 可复用 |
|---|---|---|
| 原始图片/分割 | 视图生成、重建及下游 | 无关资产 |
| 六/七视图选择 | VGGT 与下游资产版本 | 同一次六张生成图 |
| 过滤参数 | 过滤、canonical、受影响场景 | 原始预测 |
| 名称/故事 | 计划及相关场景 | 源点云 |
| 场景关系 | 对应布局、依赖检查、画面 | 模型重建 |
| 仅相机 | 该幕渲染与画面验证 | 资产与布局 |
| 仅旁白 | 文本验证、索引/视频 | 未改动图片 |

缓存键包含代码/算法版本、资产哈希、配置、模型与 prompt 版本，不能只用文件名。写临时文件 → 完整校验 → 原子提交运行记录；停止 worker 不应留下永远 running 的任务。

## 11. 风险与范围收缩

| 风险 | 诊断办法 | 保持项目可完成的处理 |
|---|---|---|
| 重建资产看不清 | 同一相机查看原图/点云，多角度抽查 | 先固定两份已合格真实资产；单独报告筛选范围 |
| 服务器没有离屏图形环境 | P1 CPU 渲染冒烟测试 | CPU 参考渲染为核心，Open3D 仅增强 |
| 三对象约束不稳定 | 可行夹具与约束残差 | 正式范围收缩到两对象，三对象作为扩展 |
| 小 LLM 格式/理解不稳定 | 开发集错误分类 | 简化 schema、限制动作、最多两次反馈；必要时换已可用 provider |
| 文学内容无法严格验证 | 拆分可检验事实与创作表达 | 数值指标评价执行，人工评价叙事 |
| 只有生成图，无三维真值 | 检查数据来源 | 不计算伪 CD；主评故事执行而非几何真实性 |
| GPU 或网络不可用 | 环境诊断和退出码 | 完成 CPU 阶段；真实模型阶段保持 blocked |
| 时间不足 | 看阶段证据而非已写代码量 | 完成 P0–P6 + 精简 P8；P7/P9 延后 |
